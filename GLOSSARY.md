# Domain Glossary: Infor ERP LN Skill Architecture

Consistent vocabulary for developing, extending, and structuring Infor ERP LN development knowledge and skills.

### Core Architecture & Runtime
- **Bshell**: The Infor LN runtime execution environment / virtual process that executes 3GL/4GL bytecode, manages database cursors, and interfaces with the UI/WebUI.
- **VRC (Version - Release - Customer)**: The layered package hierarchy in Infor LN that manages code variants and customizations (e.g., standard code `B61_c`, custom code in customer VRCs).
- **Runtime Data Dictionary**: Compiled metadata (domains, tables, forms, sessions, labels) read directly by the bshell for maximum performance, updated via "Convert to Runtime" (`crdd`).
- **Application Data Dictionary**: Editable design-time definitions stored in tools tables (`ttadv...`).

### Modern Extensibility (LN 10.8+)
- **Extension Modeler (`ttext1500m000`)**: The framework for customizing standard LN components without modifying base code ("last-mile" customization), supporting clean cloud upgrades. Authoritative coding and compilation occurs strictly in the LN UI Web interface.
- **Extension Modeler Boundary & SCM Non-Check-Out**: Extensions cannot be checked out or committed through LN Studio SCM. In LN Studio, extension scripts can only be imported via "Get" for read-only reference and debugging; direct edits to workspace `.lib` XML files are invalid and non-deployable.
- **Hook-by-Hook Local Authoring**: The workflow pattern of creating and maintaining extension source files inside the local project/repository, structured by hook/function blocks, which are then copied into individual hook windows in LN UI (`ttext1500m000`).
- **#context_on / #context_off Directives**: Native Infor LN preprocessor block directives used to encapsulate hook-level code blocks (e.g. `#context_on "before.save.object"` ... `#context_off`) within local cohesive 4GL extension source files, mapping 1-to-1 with LN UI hook entry points.
- **Agent Guide-and-Paste Protocol**: The mandatory behavioral protocol for AI agents and engineers when authoring or modifying Infor LN extensions: (1) author locally in `extensions/<type>/<comp>_ext.4gl`, (2) verify offline with `check-script` / `check_4gl_script.py`, (3) output structured step-by-step guidance in chat with LN UI `ttext1500m000` navigation and clean hook-by-hook code blocks, and (4) warn never to check out or edit in LN Studio.
- **Extension Point**: An extensible LN component type: Table, Session, Report, BOD/BDE, OData REST API, Menu, Process, or Domain.
- **Hook**: An exported function (`function extern <type> <hook-name>(...)`) called by the bshell/DAL at specific lifecycle events (e.g., `before.save.object`, `when.field.changes`, `is.valid`).
- **Session Extension (`ess`)**: Last-mile extension for standard sessions (`<pkg>/library/ess/`, `sourceType=8`), implementing UI command hooks (`function.<cmd>.is.enabled`, `function.<cmd>.is.visible`, `before.command`, `after.command`). Form command execution hooks (`.before.command`, `.after.command`) have standard `void` prototypes and must not return expressions.
- **Table Extension (`est`)**: Last-mile extension for standard tables (`<pkg>/library/est/`, `sourceType=6`), implementing DAL hooks with official `#context_on` / `#context_off` blocks.
- **Extension Modeler Declarations Include Boundary (`EXT001`)**: Architectural rule requiring all `#include` directives in Extension Modeler (`.cln`, `_ext.4gl`) to reside strictly inside `#context_on "declarations"` ... `#context_off`. Direct `#include` statements placed outside this block are ignored by the server code generator, causing unresolved function references (e.g. `dal.*`).
- **Extension Hook Scope Enforcement (`EXT002`)**: Architectural rule separating Table Extension hooks from Session Extension hooks: Table Extensions support only Table DAL hooks (no Form Command hooks), while Session Extensions support only Form Command hooks and UI handlers (no Table DAL hooks).
- **Void Function Return Constraint**: In Baan 4GL, functions and hooks declared as `void` (or defaulting to `void`) must only use bare `return` or `return()`. Passing any expression (`return(true)`, `return(0)`) is rejected by the Baan compiler (`Return value for void function not allowed`).
- **CDF (Customer Defined Field)**: Custom database columns (`<table>.cdf_<name>`) added to standard or custom tables with dedicated logic hooks.
- **Cloud Governance**: Restrictions enforced on extensions in Infor Cloud (e.g., trusted vs untrusted mode, execution time governors, query limits, restricted file system access).

### Classic 4GL & Tools (Development Tools 10.5+)
- **DAL (Data Access Layer)**: The business logic layer for tables. DAL 1 (classic) and DAL 2 (modern object-oriented style with property hooks, object sets, and business methods).
- **DAL Object Hook**: High-level CRUD lifecycle method on the entity table (e.g., `before.save.object`, `after.save.object`, `before.destroy.object`, `method.is.allowed`).
- **DAL Property Hook**: Column-specific validation/logic hook formatted as `<table.column>.<suffix>` (e.g., `.is.valid`, `.make.valid`, `.is.mandatory`, `.is.readonly`, `.update`, `.check`).
- **UI Script (4GL Script)**: Client-facing session script managing user interface interactions and choice sections. Database modifications should never be placed directly in UI scripts.
- **3GL / DLL Library**: Shared callable functions (`bic_*` libraries) providing reusable business algorithms and utility routines.
- **MMT Session (Multi-Main Table)**: Complex user interfaces coordinating multiple entity tables through an MMT Controller session and linked Satellite sessions.
- **MMT Controller (`<DR_Controller>`)**: Session archetype coordinating multi-table maintenance with linked Satellite sessions via `<ControllerSatelliteRelationship>`.
- **Satellite Session**: Child session embedded in an MMT Controller displaying related detail lines.
- **Form Command (`<FormCommand>`)**: Declarative action or toolbar button in a session bound to a 4GL function or standard choice.
- **Baan SQL (Embedded SQL)**: Embedded database queries utilizing `SELECT ... SELECTDO ... SELECTEOS ... ENDSELECT` constructs with cursor-level transaction controls (`commit.transaction()`, `retry.point()`).
- **PMC (Product Maintenance Component)**: Software distribution mechanism managing individual solutions, collections, patches, and feature packs.

### Best Practice & Design Patterns
- **Separation of Concerns (SoC)**: Architectural rule in Infor LN mandating that UI logic stays in UI scripts (`type 1-4`), while all business logic, data validations, integrity checks, and CRUD operations reside strictly in the DAL (or Table Extension).
- **Hook Lifecycle**: The deterministic call sequence of extension hooks during CRUD operations (e.g. `before.open.object.set` -> `set.object.defaults` -> `<field>.check.input` -> `before.save.object` -> `after.save.object`).
- **Index Selectivity**: Designing and selecting SQL indices where leading fields match `WHERE` equality predicates, avoiding full table scans and lock escalation.
- **Controller & Satellites**: The MMT session design pattern where a single parent Controller coordinates one or more synchronized Satellite sessions displaying related detail records.

### LN Studio (Activity-Based Development, 10.8 build 0640)
- **Activity**: The unit of work in LN Studio; every component modification is linked to an activity (`<activity> [<project>]` folder), which belongs to a software project under an application. Lifecycle: open, clean, recover, reassign, end, link run configurations.
- **Read-Only SCM Guardrail**: SCM protection mechanism where components checked into LN SCM have the OS Read-Only flag set. The toolchain enforces `assert_file_writable` and aborts with `ReadOnlyComponentError` to prevent overwriting or editing checked-in components, requiring human check-out in the Eclipse workbench.
- **BDE SCM Protocol**: The native Business Data Entity XML protocol (CmCheckOut, CmCheckIn, CmUnCheckOut) used by Infor LN Studio (com.infor.ln.studio.common.core.cm.proxies) to communicate component versioning, code payloads, and activity locks with the Infor LN Enterprise Server.
- **Server Lock (Task Workarea)**: Server-side check-out state in Infor LN repository tables (	tadv... / 	lprj...) associating an object with an active Development Activity. Without this, local workspace edits are uncommitted and subject to overwrite.
- **Verification Receipt**: Explicit server-issued confirmation containing server timestamp, version ID, and activity GUID verifying that an SCM action actually executed on the remote ERP server rather than only mutating local disk files.
- **SCM Cache (`.admin`)**: The per-activity Eclipse SCM registration file listing tracked components and their flags (`isCreated`, `isCheckedOut`, `isDirty`, `isVSCHappy`). Regenerated from disk across all 12 managed extensions by `admin_sync.py` / `sync-admin` so Studio stops reporting phantom missing components.
- **Ecore Native Datatype**: The internal integer codes used by LN Studio's Ecore metamodel (`1`=Byte, `2`=Double, `3`=Long, `5`=Numeric, `6`=String, `7`=Enum, `9`=Date, `14`=UTC).
- **Four-Layer Activity Validator (`validate`)**: Comprehensive static verification engine auditing (1) SCM `.admin` registration and Read-Only state across 12 extensions, (2) XML root/child structure and Ecore datatypes, (3) Cross-object references (`.lbl`, `.tbl`, `.mnu`), and (4) Static 4GL syntax/completion checks on `<expression>` blocks.
- **Safe `--fix` Mode**: Non-destructive automated repair that generates missing `.lbl` files and synchronizes `.admin` registration without touching or modifying Read-Only files.
- **Problem Markers (`.markers`)**: The Eclipse binary diagnostics file per activity project recording compiler errors, warnings, and line numbers; decoded by `ln_error_reader.py` / `diagnose` into line-accurate reports (errors block a build, warnings do not).
- **Workbench**: The Eclipse RCP desktop shell hosting LN Studio perspectives, views, multipage editors, wizards, and dialogs.
- **Project VRC**: The VRC holding all finished software components for a project; SCM is activated per project VRC on the LN server (and optionally per Studio application), determining VRC numbering and CM action behavior.
- **Pinned Build Identity**: The validated runtime for this skill — LN Studio 10.8 build 0640 (April 2026 tree) with the September 2025 Application Development Guide; multi-release support is out of scope.
- **VSC (Verification of Source Code)**: Infor LN source code analysis and verification tool (`ttadv1230m000` / `ttadv1231m000`) integrated into LN Studio builders via `com.infor.ln.studio.apps.core.vscmarker`, enforcing static checks and blocking/non-blocking warnings.
- **Cloud Trusted Function (`Trusted="yes"`)**: Bshell functions certified for execution in Infor LN Cloud Multi-Tenant and GovCloud environments. Calling untrusted functions in Cloud Extensions triggers verification and security rejections.
- **DAL2 Field Hook Suffixes**: The 10 standardized method suffixes recognized by LN Studio's code assist (`.is.never.applicable`, `.is.applicable`, `.is.readonly`, `.is.derived`, `.is.mandatory`, `.is.valid`, `.update`, `.make.valid`, `.check`, `.set.defaults`).
- **TextMate Grammar (`tmLanguage.json`)**: Structured JSON regex tokenization grammar conforming to VS Code's syntax highlighting engine, classifying Baan 4GL code into scopes for colors and themes.
- **Standalone 4GL Auditor (`audit_4gl.py`)**: Zero-dependency offline verification engine in `erp-ln-progguide/scripts/` validating 4GL, DAL2, and UEDLL code against Studio syntax rules, DAL contracts, Cloud governance, and anti-pattern caveats.

### Headless JCA Connectivity, Remote SCM & MCP Architecture (ADR 0007)
- **JCA Adapter (`JCAAdapter4ERPln`)**: The pure-Java JCA 1.6 connector (`com.infor.erpln.jca.*` and `com.infor.erpln.protocol.*`) bundled in LN Studio that communicates with `<GatewayURL>/<TenantID>/LN/webservice` over HTTPS (`http_oauth2`) using XML BDE payloads and `User-Agent: JCAWebClient (LNStudio)`.
- **ION API Credentials (`.ionapi`)**: JSON configuration file issued by Infor ION API Gateway containing Tenant ID (`ti`), Gateway URL (`iu`), OAuth2 Provider endpoints (`pu`, `oa`, `ot`, `or`), Client ID/Secret (`ci`, `cs`), and optional Service Account credentials (`saak`, `sask`).
- **Cloud Environment Preference (`cloudenv.prefs`)**: Global Eclipse installation preference file (`com.infor.erpln.jca.connectivity.cloudenv.prefs`) storing imported `.ionapi` OAuth2 endpoints and tenant definitions across workspaces.
- **JCA Connection Point (`connectivity.prefs`)**: Per-workspace Eclipse preference file (`com.infor.erpln.jca.connectivity.prefs`) defining `ProjectServer` (`http_oauth2`) and shared `<Project>_dev` / `<Project>_rt` (`bw` shared connection) endpoints.
- **BDE Dispatch (`doBdeCall`)**: The core RPC mechanism of LN Studio where operations on Software Projects (`SoftwareProject_V2`), Activities (`FglStudio`, `CMLabel`), Component Explorers (`Group`, `StudioComponent`), and TDE Components (`DR_Table`, `DR_Controller`, `DR_Module`, `DR_Report`, `DR_Domain`, `DR_Label`, `DR_Message`, `DR_Question`, `DR_Menu`, `DR_AdditionalFile`) are invoked as XML request/response documents.
- **Pre-Commit SCM Boundary**: The safety governance rule (ADR 0007) allowing `ln_studio_skill` and its MCP server to automate `Get`, `Create Activity`, `Check-Out`, `Undo Check-Out`, `Put`, `DR_Create`, `Compile`, `ConvertToRuntime`, and `Check-In` (for testing on the Activity VRC `ext` in LN UI Cloud), while strictly hard-blocking `End Activity` / `Commit Activity` (`CloseTask` / `FinalizeActivity`) so a human engineer performs the final delivery approval.
- **`deploy-test` Pipeline**: Composite headless workflow (`Put/DR_Create -> Compile -> ConvertToRuntime/CreateTables -> executeVSC -> CheckIn`) that pushes local component changes to the LN Server Activity VRC and makes them immediately testable in LN UI Cloud while returning line-accurate compiler diagnostics.
- **`prepare-end-activity` Gate**: Pre-commit verification command that runs `DR_Solution.ValidateDevelopmentActivity` and `ExecuteVSC` on the server, verifies 100% Eclipse workspace metadata synchronization (`.admin`, `.project`, `properties.index`), and generates a human-readable activity summary before manual Activity completion in LN Studio.
- **LN Studio MCP Server (`ln_studio_mcp.py`)**: Stdio Model Context Protocol server exposing LN Studio connectivity, remote explorers, 12-type component generation, server cloning, and pre-commit SCM/build workflows as native AI agent tools.


### Semantic/AST Verification, DD Cache & Production Hardening (ADR 0008)
- **Data Dictionary Schema Cache (`.ln_dd_cache.json`)**: Workspace-level JSON index mapping Infor LN table codes (`.tbl`) to their columns, domains, datatypes, and primary/secondary index keys, and domain codes (`.dmn`) to their native datatypes and enumeration constants. Automatically populated whenever `get` or `sync-reference` fetches `.tbl`/`.dmn` XMLs from the server.
- **Table Declaration Enforcement (`TBL001`)**: Semantic rule in `audit_4gl.py` verifying that every `<table>.<field>` referenced in 4GL statements or embedded SQL (excluding the component's main table) has a corresponding `table t<table>` declaration in the `declaration:` section.
- **Schema Field & Domain Verification (`TBL002` & `DMN001`)**: Schema-aware rules in `audit_4gl.py` verifying that every referenced `<table>.<field>` and `domain <domain_name>` exists in `.ln_dd_cache.json` (with optional `--auto-fetch-dd` to pull missing `.tbl`/`.dmn` definitions read-only from the server).
- **Intra-File Call Graph Transaction Audit (`CAV003`)**: AST-based static analysis in `audit_4gl.py` that constructs a function call graph within a 4GL/DAL script to detect both direct and transitive nested transactions (calling a helper function that executes `db.retry.point()`, `commit.transaction()`, or `abort.transaction()` inside an active transaction block).
- **3-Tier Automated OAuth2 Lifecycle**: Token management architecture in `ln_env_manager.py` persisting tokens in `~/.ln_studio/tokens/<workspace>.json`: (1) Cached Active Token with a 5-minute safety buffer, (2) Silent Refresh via `refresh_token` or Service Account `saak`/`sask`, and (3) Interactive Browser (`webbrowser.open`) with loopback listener or `--manual-auth` URL/code paste fallback for `oob://localhost/lnstudio`.
- **Workspace Reference Sync (`sync-reference`)**: Read-only component synchronization command storing reference tables, domains, sessions, and extensions in `<workspace>/.reference/<type>/` without registering them into any Activity `.admin` file, while automatically indexing `.tbl` and `.dmn` schemas into `.ln_dd_cache.json`.
- **BYOJ (Bring Your Own JARs)**: Licensing compliance architecture where no proprietary Infor JARs (`JCAAdapter4ERPln*.jar`, `com.infor.ln.studio.common.core*.jar`) are tracked in Git; instead, `ln_server_client.py` and `admin_sync.py` dynamically discover JARs from `LN_STUDIO_HOME` or local Eclipse LN Studio installations.
- **Split `deploy-test` Modes (`compile-only` vs `schema-crdd`)**: Operational safety separation where `deploy-test` defaults to `--mode compile-only` (`Put -> Compile -> VSC -> CheckIn`) to avoid database/table lock hangs, reserving `ConvertToRuntime` (`CRDD`) and `CreateTables` for explicit `--mode schema-crdd` executions with pre-check lock warnings.

### 100% Eclipse LN Studio Parity, Persistent JCA Daemon & Bytecode Ground Truth (ADR 0012)
- **Persistent JCA Daemon (`LNStudioJcaBridge --daemon`)**: Background JVM daemon per workspace listening on `127.0.0.1:<port>` that holds a single persistent JCA connection (`Pool Size = 1` bshell per connection point) with a sequential FIFO command queue, dynamic OAuth2 token hot-swap, and 30-minute idle auto-shutdown.
- **5-Mode `BdeManager` Dispatch (`Template.java`)**: The five execution modes of `com.infor.erpln.jca.connectivity.BdeManager`: `LIST` (`executeList`), `SHOW` (`executeShow`), `BDE` (`executeMethod`), `SPECIALLIST` (`executeSpecialList`), and `BROWSELIST` (`executeList` with controlling attributes).
- **Controlling Attributes (`setSpecificControlAttributeMetaData`)**: JCA BDE control header metadata (`"{methodName}:{attrName}:{in|out}"`) required by operations such as `GetBrowseList` (`package`, `type`, `includeExpired`), `ConvertToRuntime` (`executionMethod=synchronous`), and `CreateTables` (`executionMethod=synchronous`).
- **Task `labelUUID` (`Label` Property)**: The unique server-generated SCM activity UUID returned by `SoftwareProject_V2` in `<labelUUID>` and stored in Eclipse `ProjectProperties` under the key `"Label"`. Must be passed inside `<ActivityID><activityUUID>` (distinct from `<taskUUID>`, which holds the PMC Solution code).
- **Binary `PropertyBucket` (`properties.index`)**: The Eclipse `org.eclipse.core.internal.properties.PropertyBucket` big-endian `DataOutputStream` binary file at `<workspace>/.metadata/.plugins/org.eclipse.core.resources/.projects/<ProjectFolder>/.indexes/properties.index` where `ProjectProperties` stores activity, VRC (`ApplicationRelease`), and repository bindings.
- **Native Single-XML TDE Layout (`TDEResource`)**: Authentic LN Studio workspace directory layout storing each component as a single XML file with embedded `<DR_Module><Source><expression>` (for `.ses`/`.tbl`) or `<Source><expression>` (for `.lib`/`.fnc`/`.rpt`) at `{pkg}/{type}/{mod}/{name}.{ext}` (module-scoped) or `{pkg}/{type}/{name}.{ext}` (`domain`, `label`, `message`, `question`).
- **Ad-Hoc Server Compile (`FglStudio.compileSource`)**: BDE operation on `FglStudio` that compiles an arbitrary 4GL source buffer on the server (`bic6.2`) and returns line-accurate `<compileResult>` diagnostics without checking out or modifying workspace files.
- **Server Code Intelligence (`FglStudio` Search & Call Hierarchy)**: Server-side BDE capabilities including `FglStudio.Searchpattern` (global regex search across packages), `fglstudio.GetCallHierarchyData` (where-used callers/callees), `FglStudio.OpenDeclarationFunction`, and `FglStudio.GetRevisions` / `StudioComponent.GetRevision` (version history and structural diff).
