# s3.delete.folder()

## Syntax:
`function long s3.delete.folder( const string s3.path$, [ const string progress.callback.dll$, const string progress.callback.function$, long progress.callback.data ] )`

## Description
Deletes an S3 folder including the complete tree of files and folders below it.
It is possible to pass a progress callback function. This callback function can be used to update an already created progress indicator. The callback function is called right before and after a file is deleted. It must have the following prototype:
```

extern long <progress_function>(
   long total.count,            |* total number of files to delete
   long actual.count,           |* number of files that have been deleted so far
   const string source.path$,   |* the name of the file being deleted
   const string target.path$,   |* an empty string, indicating a delete is done
   long data)                   |* any progress callback data, can be XML/JSON
```
This callback function must return 0 to continue, or <> 0 (like `PROGRESS.STOP`) to stop deleting files.
Example:
```

function long delete.s3.folder(const string s3.folder$)
{
        long    error

        |* delete an S3 folder including everything below it, and show progress

        create.progress.indicator("Delete S3 Folder", PROGRESS.BAR + PROGRESS.STOP + PROGRESS.NOAUTODESTROY)
        error = s3.delete.folder(s3.folder$, __OBJECT__, "report.s3.progress")
        destroy.progress.indicator()
        return(error)
}

|* next function is the progress callback function
function extern long report.s3.progress(long total.count, long actual.count,
        const string source.path$, const string target.path$, long data)
{
        return(change.progress.indicator(actual.count * 100 / total.count,
                sprintf$("Deleting: %s", source.path$)))
}
```

## Arguments
| | | |
|---|---|---|
| `const string` | `s3.path$` |  an S3 path denoting a folder; this is a single byte string of max `S3_PATH_SIZE (1088)` bytes  |
| `[ const string` | `progress.callback.dll$ ]` |  the DLL in which the progress callback function is located  |
| `[ const string` | `progress.callback.function$ ]` |  the progress callback function name  |
| `[ long` | `progress.callback.data ]` |  any data you want to pass to the progress callback function; this can be JSON or XML  |

## Return values
| | |
|---|---|
| `0` | Success |
| `<> 0` | In case progress was stopped, `S3_PROGRESS_STOPPED (-99)` is returned; in case of an error this is the system error code, like `EACCES`, `EINVAL`, etc.  |
Notes
- In case of an error, the predefined variable `e` is set as well.
- You can call ` [s3.error.argument$](s3.error.argument$.md)` to get the name of the argument that caused the error.

## Context
This function is implemented in the 4GL Tools and can be used in all script types. This function is available from [TIV](../tiv/tiv_overview.md) level 2510.
This function is marked as 'conditionally trusted' and can therefore only be used in trusted objects or 'conditionally' in not trusted objects. More about trusted and not trusted objects can be found in the section about [managed execution.](../misc/managed_execution.md).
