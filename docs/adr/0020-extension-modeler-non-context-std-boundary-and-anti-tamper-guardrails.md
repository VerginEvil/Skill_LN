## 1. Context & Problem Statement

When engineers copy raw 4GL Extension scripts (Table Extensions `txest*` or Session Extensions `txess*`) from Infor LN Studio into local projects to continue development with AI agents, the raw script contains two distinct categories of code:
1. **Auto-Generated Standard Framework Code (Outside `#context`)**:
   - Header comments and SCM metadata warnings.
   - Declarations under `| Additional generated declarations` (e.g., `table <tbl>`, `#include <bic_dal2>`, `#include <bic_tableext>`, `#include <bic_text>`).
   - Standard framework and metadata functions generated by Extension Modeler (`get.extension.point.version()`, `ext.is.cdfs.of.ref.tables.selected()`, `ext.get.form.fields()`, `ext.get.session.indices()`, `ext.get.command.extensions()`, `ext.get.report.extensions()`).
2. **Custom Hook Code (Inside `#context_on "<hook>"` ... `#context_off`)**:
   - Developer-authored business logic, property validations, event handlers, and custom helper functions.

### The Problem:
AI coding assistants repeatedly misunderstood this dual structure:
- **Tampering with Standard Boilerplate**: Agents edited, deleted, or reformatted framework functions outside `#context`.
- **Relocation of Code**: Agents attempted to "clean up" the script by moving standard table/include declarations into `#context_on "declarations"`.
- **Rule EXT001 False Positives**: The prior definition of `EXT001` flagged any `#include` outside `#context_on "declarations"`, causing agents to aggressively relocate standard generated includes into `#context_on "declarations"`.

---

## 2. Settled Decisions

### Decision 1: Strict Non-Context Read-Only Immutability
All lines of code located outside `#context_on "<hook>"` ... `#context_off` directives are strictly **Read-Only / Immutable**. AI agents and automated tools must never modify, delete, reformat, or insert code outside `#context_on ... #context_off`.

### Decision 2: Automatic Extension Script Recognition
Any 4GL source file containing `#context_on` or `#context_off` directives is automatically recognized as an Infor LN Extension Modeler script. AI agents must immediately apply the non-context read-only policy without requiring explicit user instructions.

### Decision 3: Strict No-Relocation Policy
Agents must never relocate declarations, `#include` statements, or functions between the non-context standard section and `#context` blocks:
- Standard `table` and standard `#include` statements generated under `| Additional generated declarations` must remain untouched in place.
- All new custom variables, tables, or custom `#include` directives must be declared strictly within `#context_on "declarations"`.

### Decision 4: EXT001 Refinement for Standard Generated Includes
Rule `EXT001` is refined to differentiate between standard generated includes and custom includes:
- Direct `#include` statements within the standard `| Additional generated declarations` section (e.g. `<bic_dal2>`, `<bic_tableext>`, `<bic_text>`, `<bic_interface>`) are permitted and recognized as standard boilerplate.
- Custom `#include` statements (such as custom DLLs `otxslidll...`) placed outside `#context_on "declarations"` remain strictly prohibited and flagged under `EXT001 [ERROR]`.

### Decision 5: Anti-Tamper Audit Rule EXT003
Introduce rule `EXT003` in `scripts/audit_4gl.py` and `ln_studio_skill/tools/check_4gl_script.py`:
- Flag any modification or deletion of standard framework functions (`get.extension.point.version`, `ext.get.form.fields`, `ext.get.command.extensions`, etc.).
- Flag any unclosed, nested, or malformed `#context_on` / `#context_off` pairs.
- Flag any custom executable functions declared outside `#context_on` blocks.

### Decision 6: Dual-Mode Delivery Workflow
When an agent completes an extension modification:
1. **Local Repository Preservation**: Save the cohesive `.4gl` file preserving all standard non-context boilerplate.
2. **Chat Guide-and-Paste**: Output clean hook code blocks in chat (stripped of `#context` wrappers) alongside LN UI (`ttext1500m000`) navigation instructions for seamless 1-click deployment.

---

## 3. Architecture Comparison

| Dimension | Previous Defective Behavior | ADR 0020 Authoritative Rule |
|---|---|---|
| **Non-Context Code** | Erroneously edited, refactored, or reformatted | Strictly Read-Only / Immutable |
| **Code Relocation** | Tables/includes moved into `#context` | Strictly prohibited; preserved in place |
| **Rule EXT001** | Flagged standard includes outside context | Permits standard boilerplate; flags only custom includes |
| **Tamper Detection** | None | `EXT003 [ERROR]` detects structural corruption |
| **Local .4gl File** | Corrupted or stripped of standard functions | Full-fidelity raw source preserved |
